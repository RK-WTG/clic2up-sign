1. Presentation generale

1.1 Contexte et objectif

clic2up-sign est un service local Windows qui permet a l'application web clic2up de signer electroniquement des factures au format TEIF (Tunisian Electronic Invoice Format) conformement aux specifications ElFatoora de Tunisie TradeNet.

La signature electronique necessite un acces materiel a une cle USB cryptographique (token) contenant le certificat du signataire. Les navigateurs web ne pouvant pas acceder directement au materiel USB, clic2up-sign fait office de pont entre l'application web et la cle USB via un serveur HTTP local.

Pourquoi un service local ?
Un navigateur web ne peut pas acceder a une cle USB via PKCS#11. clic2up-sign joue le meme role que TunSign pour le portail ElFatoora : il recoit les requetes HTTP du navigateur, accede a la cle USB, signe le document et retourne le resultat.

1.2 Architecture

+----------------------------------------------------------+ | Machine du client | | | | +------------+ localhost:9876 +----------------+ | | | React | --- POST /sign ----> | clic2up-sign | | | | Frontend | <-- XML signe ------ | (.exe Windows) | | | +-----+------+ +-------+--------+ | | | | PKCS#11 | | | +------+--------+ | | | | SafeNet + | | | | | Cle USB | | | | +---------------+ | +--------|-------------------------------------------------+ | HTTPS +----+------+ | Backend | | NestJS | +----+------+ | +----+------+ | AWS S3 | | (stockage)| +-----------+

1.3 Flux de signature

  1. L'utilisateur clique "Signer" sur une facture dans clic2up
  2. Le frontend genere le XML TEIF (sans bloc signature)
  3. Le frontend demande le code PIN a l'utilisateur
  4. Le frontend envoie le XML + PIN au service local (POST http://localhost:9876/sign)
  5. clic2up-sign accede a la cle USB via le driver SafeNet (PKCS#11)
  6. clic2up-sign construit la signature XAdES-BASELINE-B et signe le document
  7. Le XML signe complet est retourne au frontend
  8. Le frontend envoie le XML signe au backend NestJS pour stockage sur S3

3.2 Classes Java

Main.java

Point d'entree de l'application. Gere deux modes de fonctionnement :

  • Mode serveur (par defaut) : lance le serveur HTTP + icone system tray
  • Mode CLI : commandes en ligne (signer, valider, lister certificats)

Commandes disponibles :

CommandeDescription
server [--port 9876]Lance le serveur HTTP
signer-token <xml> <driver> <pin> <sortie>Signe avec cle USB
signer-p12 <xml> <p12> <mdp> <sortie>Signe avec fichier PKCS#12
valider <xml_signe>Valide une signature
lister-token <driver> <pin>Liste les certificats USB
lister-p12 <p12> <mdp>Liste les certificats PKCS#12

SigningServer.java

Serveur HTTP base sur Javalin exposant l'API REST sur localhost:9876. Configure le CORS pour les origines autorisees et route les requetes vers les handlers.

ElFatooraSignature.java

Coeur du systeme. Implemente la signature XAdES-BASELINE-B conforme aux specifications ElFatoora en utilisant la librairie EU DSS. Gere le nettoyage du XML, la creation des parametres de signature et l'injection de la signature dans le document.

Pkcs11TokenJDK17.java

Wrapper de compatibilite. La librairie DSS 6.0 utilise l'ancienne API PKCS#11 (new SunPKCS11(InputStream)) supprimee dans JDK 9+. Cette classe utilise l'API moderne Provider.configure(String) introduite dans JDK 9.

ElFatooraValidation.java

Valide les signatures XAdES sur les documents XML signes en utilisant le framework de validation de DSS (mode hors-ligne, sans verification OCSP/CRL).

XmlUtils.java

Utilitaires de preparation XML : conversion en format compact (unpretty), detection de caracteres problematiques, verification de signatures existantes.

SystemTrayManager.java

Gere l'icone dans la barre des taches Windows avec menu contextuel et notification de demarrage. Utilise une Frame invisible de type UTILITY pour forcer l'initialisation AWT en mode GUI.

5. Signature electronique

5.1 Standard XAdES-BASELINE-B

La signature utilise le standard europeen XAdES-BASELINE-B (XML Advanced Electronic Signatures) defini par le reglement eIDAS. C'est le niveau de base qui garantit :

  • L'integrite du document (toute modification invalide la signature)
  • L'authentification du signataire (certificat inclus)
  • La non-repudiation (le signataire ne peut pas nier avoir signe)

Parametres de signature

ParametreValeur
NiveauXAdES-BASELINE-B
PackagingENVELOPED (signature dans le XML)
Algorithme de hachageSHA-256
Algorithme de signatureRSA-SHA256
Role du signataireFournisseur

5.2 Politique de signature ElFatoora

ChampValeur
OIDurn:2.16.788.1.2.1
DescriptionPolitique de signature de la facture electronique
QualificateurOID_AS_URN
URL du documenthttp://www.tradenet.com.tn/portal/telecharger...
Hachage de la politiqueSHA-256

5.3 Acces a la cle USB (PKCS#11)

L'acces a la cle USB SafeNet se fait via le standard PKCS#11 (Cryptographic Token Interface Standard).

Driver SafeNet

ProprieteValeur
Driver par defautC:\Windows\System32\eTPKCS11.dll
Provider JavaSunPKCS11
Type de KeyStorePKCS11
Compatibilite JDK 17 : La librairie DSS 6.0 utilise l'ancienne API new SunPKCS11(InputStream) supprimee dans JDK 9. La classe Pkcs11TokenJDK17 corrige ce probleme en utilisant l'API moderne Security.getProvider("SunPKCS11").configure(config).

Configuration PKCS#11

--name=clic2up-sign
library=C:\Windows\System32\eTPKCS11.dll

6. Compilation et packaging

6.1 Compilation du JAR

La compilation cree un fat JAR contenant toutes les dependances :

mvn clean package

Resultat : target/clic2up-sign.jar (~29 MB)

Le fat JAR est cree par maven-shade-plugin qui :

  • Inclut toutes les dependances dans un seul JAR
  • Merge les fichiers META-INF/services (SPI) avec ServicesResourceTransformer
  • Filtre les fichiers de signature (*.SF, *.DSA, *.RSA)
  • Configure le manifest avec la classe principale com.clic2up.Main

6.2 Packaging en executable Windows

L'outil jpackage (inclus dans le JDK 17) cree un executable autonome avec un JRE embarque :

build-exe.bat

Ce script execute :

jpackage --type app-image
         --name clic2up-sign
         --input packaging\input
         --main-jar clic2up-sign.jar
         --main-class com.clic2up.Main
         --dest dist
         --java-options "-Xmx256m"
         --add-modules java.base,java.compiler,java.desktop,
                       java.instrument,java.management,java.naming,
                       java.security.jgss,java.sql,java.xml.crypto,
                       jdk.crypto.cryptoki
         --jlink-options "--strip-debug --no-header-files --no-man-pages"

Resultat : dossier dist/clic2up-sign/ contenant l'executable et le JRE.

6.3 Creation de l'installeur

L'installeur Windows est cree avec Inno Setup 6 :

build-installer.bat

Ce script enchaine trois etapes :

  1. Generation de l'icone (generate-icon.java) : cree le fichier .ico
  2. Packaging jpackage (build-exe.bat) : cree l'app-image
  3. Compilation Inno Setup (ISCC.exe clic2up-sign.iss) : cree l'installeur

Resultat : dist/clic2up-sign-setup.exe

6.4 Optimisations

OptimisationEffet
--add-modules (10 modules sur ~70) JRE : 129 MB → 71 MB
--strip-debug --no-header-files --no-man-pages Supprime les symboles de debug et fichiers inutiles

7. Installation

7.1 Pre-requis

Pre-requisDetails
Systeme d'exploitation Windows 10 / 11 (64 bits)
SafeNet Authentication Client Installe avec le driver eTPKCS11.dll
Cle USB cryptographique Token contenant le certificat de signature (TnTrust)
Espace disque ~150 MB
Pas besoin d'installer Java ! Le JRE est embarque dans l'executable. L'utilisateur n'a besoin d'aucune installation Java sur sa machine.

7.2 Procedure d'installation

  1. Executer clic2up-sign-setup.exe
  2. Ecran d'accueil : cliquer "Suivant"
  3. Information : lire les pre-requis, cliquer "Suivant"
  4. Dossier d'installation : choisir le dossier (defaut : C:\Program Files\clic2up-sign)
  5. Options :
    • Creer un raccourci sur le Bureau (recommande)
    • Lancer automatiquement au demarrage de Windows (recommande)
  6. Installation : les fichiers sont copies
  7. Lancement : le service demarre automatiquement
  8. Un message confirme que le service est actif

Apres l'installation

  • Une icone apparait dans la barre des taches (pres de l'horloge)
  • Le service est accessible sur http://localhost:9876/status
  • Si le demarrage automatique est active, le service se lance a chaque demarrage de Windows

7.3 Desinstallation

Via Parametres Windows → Applications → clic2up-sign → Desinstaller.

La desinstallation :

  • Arrete le processus en cours
  • Supprime tous les fichiers installes
  • Retire les raccourcis (Bureau, Menu Demarrer, Demarrage)

9. Securite

Communication

  • Le service ecoute uniquement sur localhost (127.0.0.1) — inaccessible depuis le reseau
  • CORS strictement configure : seules les origines autorisees peuvent appeler l'API
  • Le code PIN n'est jamais stocke — il transite uniquement en memoire le temps de la signature

Cle USB

  • La cle privee ne quitte jamais le token USB — la signature est realisee sur le token
  • Le code PIN est verifie par le token lors de chaque operation de signature
  • Apres plusieurs tentatives de PIN incorrect, le token se bloque (protection hardware)

Application

  • Aucune donnee n'est stockee localement par clic2up-sign
  • Le fichier log (~/clic2up-sign.log) ne contient jamais de PIN ou de donnees sensibles
  • L'application ne necessite pas de droits administrateur pour fonctionner
Registre Windows : Contrairement a TunSign qui utilise CAPI (et necessite la modification de la cle DisableCapiOverrideForRSA), clic2up-sign utilise PKCS#11 directement. Aucune modification du registre Windows n'est necessaire.

10. Depannage

Probleme Cause probable Solution
Le service ne repond pas Le service n'est pas lance Lancer clic2up-sign.exe ou verifier le demarrage automatique
CKR_PIN_INCORRECT Mauvais code PIN Verifier le PIN. Attention : apres plusieurs erreurs, le token se bloque
Aucune cle trouvee Cle USB non connectee Brancher la cle USB et verifier que SafeNet la detecte
SunPKCS11 not available Probleme JRE Reinstaller clic2up-sign
Error configuring SunPKCS11 Driver SafeNet non trouve Verifier que SafeNet Authentication Client est installe
Le port 9876 est occupe Une autre instance tourne deja Fermer l'autre instance via le Gestionnaire des taches
Erreur CORS dans le navigateur Origine non autorisee Verifier que l'URL du frontend est dans la liste des origines CORS
L'icone n'apparait pas Masquee par Windows Cliquer sur la fleche ^ pres de l'horloge, ou activer dans Parametres > Barre des taches

Fichier de log

En cas de probleme, consultez le fichier de log :

C:\Users\<votre_nom>\clic2up-sign.log
